# Markdown Notes on Android (React Native / Expo)

Same codebase as iOS. `android/` is generated by Expo prebuild (Continuous Native Generation) and is
git-ignored, like `ios/`. Application id `com.mdnotes.reactnative`, app name `Markdown Notes`.

## Build the release APK from a clean checkout

Requirements: Node.js 22+, JDK 17, Android SDK (+ the NDK/CMake versions Gradle requests; it installs
them automatically when the SDK licenses are accepted). All commands run from `react-native/`.

```sh
export ANDROID_HOME=~/Library/Android/sdk
export JAVA_HOME=$(/usr/libexec/java_home -v 17)

npm ci
CI=1 npx expo prebuild --platform android --clean      # generates android/

cd android
./gradlew assembleRelease                               # all ABIs
# faster, emulator/device ABI only: ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
cd ..
echo "$PWD/android/app/build/outputs/apk/release/app-release.apk"
```

Install/run: `adb -s emulator-5554 install -r android/app/build/outputs/apk/release/app-release.apk && adb -s emulator-5554 shell monkey -p com.mdnotes.reactnative 1`

The release APK embeds the Hermes JS bundle (no Metro needed). Like the default Expo template, it
is signed with the debug keystore. That works for emulators and sideloading. For Play Store,
configure a real upload key (or use EAS Build).

## Report

Verified on the `emulator-5554` emulator (Pixel 5, Android 15, arm64) with a release build.

### Worked out of the box (no changes)

- **Prebuild and release build**: succeeded with no project changes. `app.json` already had the `android.package` id and adaptive icons.
- **Runtime**: the app ran, with expo-sqlite storage, `marked` parsing and all custom-drawn
  controls. The insets are correct even though Android 15 forces edge-to-edge:
  `react-native-safe-area-context` pads content under the status bar and keeps the tab bar above
  the gesture-nav bar.
- **Screens**: Notes, Starred, Settings and the Preview editor match the reference PNGs. The font
  is Roboto instead of SF Pro, so text widths differ slightly.
- **Features**: these all worked out of the box:
  - seed notes and the `n/total done` footer
  - live search
  - tag filter chips
  - preview and edit modes
  - autosave, with persistence after a force-stop and relaunch
  - star
  - checklist toggle, which rewrites the body and updates the progress count
  - Delete with the 4 s toast and Undo
  - Sort by Updated/Title
  - Show snippets switch
  - Reset sample notes
  - Appearance System/Light/Dark, persisted. System follows `cmd uimode night yes/no` live.
- **Share**: React Native's `Share.share` opens the Android share sheet ("Sharing text") with the
  raw markdown. Back dismisses it and returns to the editor unchanged.

### What had to change (3 files, all shared code, Android-only branches via `Platform`)

| File | Change | Why |
|---|---|---|
| `src/theme.ts` | `mono` = `Menlo` on iOS, `monospace` elsewhere | Android has no Menlo. Code blocks, inline code and the editor fell back to the proportional default font. |
| `src/markdown/MarkdownView.tsx` | inline-code padding font = `System` on iOS, `sans-serif` on Android | Same font-name portability issue. |
| `src/screens/EditorScreen.tsx` | listens to `keyboardDidShow/Hide` on Android (`keyboardWill*` on iOS) and adds the bottom inset to the keyboard height on Android | Android never fires `keyboardWill*`, so the edit card ran underneath the keyboard. RN on Android reports the IME height minus the nav-bar inset, and the edge-to-edge window is not resized. |
| `src/screens/EditorScreen.tsx` | `BackHandler` for `hardwareBackPress` that runs the same logic as `‹ Notes` | The Android back button or gesture closed the whole app from the editor. It now returns to the originating tab. It also deletes an empty note, the same as the on-screen back button. |

No native files, dependencies or `app.json` entries were added. The iOS Release simulator build from
`BUILD.md` still succeeds.

### Still not identical / known gaps on Android

- **Fonts**: Roboto and Android `monospace` instead of SF Pro and Menlo. Metrics differ slightly,
  so line wraps can fall in different places than in the iOS references.
- **Keyboard timing**: Android only has `keyboardDidShow`, so the edit card resizes right after the
  keyboard finishes animating instead of moving with it. The gap above the keyboard was checked
  visually (about 16 pt), not measured to the pixel.
- **Keyboard appearance**: `keyboardAppearance` is iOS-only. Gboard uses its own theme, so it can
  stay light while the app is in Dark mode.
- **Launch background**: `userInterfaceStyle` needs `expo-system-ui` on Android (a prebuild
  warning). The app follows light/dark at runtime without it. However, with the app set to Dark
  and the OS in light mode, the native window background on launch is the light `#F5F5F7` until
  JS renders.
- **Accessibility ids**: `testID` maps to the Android resource-id, so ids show up in uiautomator.
  The `toast` container is the exception: a non-accessible plain View, it is not exposed as its
  own node. `undo-button` is exposed.
- **Release signing**: the release APK uses the debug keystore (template default). No production
  keystore is configured.
